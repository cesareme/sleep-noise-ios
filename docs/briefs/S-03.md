### A1 · `NightWindow` (C40, §1 regla 7)

Una sola ventana horaria para toda la app: de 21:00 a 07:00, hora local. Dentro no se vende nada (C08) ni se enseña ningún tip.

```swift
enum NightWindow {
    static let startHour = 21   // 21:00:00 is inside
    static let endHour = 7      // 07:00:00 is outside
    static func contains(_ date: Date, calendar: Calendar = .current) -> Bool
    static func isNight(calendar: Calendar = .current, now: () -> Date = { Date() }) -> Bool
}
```

- `contains`: cierto si la hora local es 21 o más, o menor que 7.
- `isNight`: `contains(now(), calendar: calendar)`. El reloj entra como closure para que nadie llame a `Date()` por su cuenta.
- Enum sin casos, sin estado.

- `testWindowOnClockChangeNights`: las madrugadas del 29-03-2026 y del 25-10-2026 en Europe/Madrid. Desde las 00:30 locales, suma minutos de uno en uno hasta 240 a ese instante base (`addingTimeInterval`); todos dentro de la ventana. No construyas las 02:00 del 29-03 con `DateComponents`: esa hora no existe.

### A2 · `NightTrial`, la prueba de 7 noches (C07, PLAN-SIMPLE §4.2)

Reglas de producto:

- La prueba **solo empieza** con el botón "Empezar la prueba · 7 noches" de la hoja Pro. Nunca con Play, ni al lanzar, ni desde un intent. Antes de empezar no da acceso: es el nivel gratuito.
- Dura 7 × 86 400 s desde ese toque (08 §2.4).
- **Se evalúa solo al arrancar una sesión de sonido.** Si los siete días se cumplen a las 03:10 con el sonido en marcha, no cambia nada hasta el siguiente arranque.
- Atrasar el reloj no devuelve tiempo (misma aritmética que `TrialClock.observe`).
- El estado vive en Keychain, detrás de un protocolo.

En `NightTrial.swift`:

```swift
struct TrialRecord: Codable, Equatable {
    var startedAt: Date
    var lastSeen: Date
    var consumed: TimeInterval
}

protocol TrialStorage {
    func loadTrial() -> TrialRecord?
    @discardableResult func saveTrial(_ record: TrialRecord) -> Bool
}

/// In-memory double for tests and previews.
final class InMemoryTrialStorage: TrialStorage {
    private(set) var record: TrialRecord?
    private(set) var saveCount = 0
    init(record: TrialRecord? = nil)
}

enum NightTrialStatus: Equatable { case notStarted, active, ended }

struct NightTrial {
    static let nights = 7
    static let length: TimeInterval = TimeInterval(nights) * 86_400
    private(set) var record: TrialRecord?
    private(set) var grantsFullAccess: Bool
    var status: NightTrialStatus { get }

    init(storage: TrialStorage)
    @discardableResult mutating func start(now: Date) -> Bool
    @discardableResult mutating func evaluateAtSessionStart(now: Date) -> Bool
    func nightsRemaining(now: Date, calendar: Calendar = .current) -> Int?
}
```

El nombre `TrialState` ya existe en `PurchaseManager.swift`: no lo reutilices.

Comportamiento exacto:

- `init`: carga el registro. `grantsFullAccess` es `consumed < length` si hay registro y `false` si no. **No lee ningún reloj.**
- `status`: sin registro, `.notStarted`; con registro, `.active` si `grantsFullAccess` y `.ended` si no.
- `start(now:)`: si ya hay registro, devuelve `false` y no escribe nada (una prueba terminada no se repite). Si no, crea `(now, now, 0)`, lo guarda, pone `grantsFullAccess` a `true` y devuelve `true`.
- `evaluateAtSessionStart(now:)`: sin registro devuelve `false` y **no guarda nada** (Play nunca empieza la prueba). Con registro: si `now > lastSeen`, suma la diferencia a `consumed`; si `now != lastSeen`, actualiza `lastSeen` y guarda; recalcula `grantsFullAccess = consumed < length` y lo devuelve.
- El comentario `///` de `evaluateAtSessionStart` incluye esta frase: "Callers must not call this when resuming after an interruption or for Small Hours." (08 §2.4). La función no puede saberlo: es un contrato para quien la cablee.
- Ningún otro método cambia `grantsFullAccess`.
- `nightsRemaining(now:calendar:)`: `nil` si `status` no es `.active`. Si lo es: `restante = max(0, length − (consumed + max(0, now − lastSeen)))`, `fin = now + restante`, y el resultado es el número de días de calendario entre `calendar.startOfDay(for: now)` y `calendar.startOfDay(for: fin)`, con suelo 1. Es la cifra de "prueba · quedan n noches" (08 §2.4). Hay una pregunta abierta sobre ella (08 §9, punto 3): por eso vive en una sola función y no la usa nadie más.

Tests en `NightTrialTests` (todos con `InMemoryTrialStorage`; día 0 = 16-11-2026 23:00 en Europe/Madrid):

- `testNotStartedGrantsNothing`: recién creada, `.notStarted`, sin acceso; `evaluateAtSessionStart` devuelve falso y `saveCount` sigue en 0; `nightsRemaining` es `nil`.
- `testStartIsExplicitAndHappensOnce`: `start` devuelve cierto y guarda una vez; un segundo `start` un día después devuelve falso y `startedAt` no cambia.
- `testEndsAfterSevenTimesTwentyFourHours`: evaluar en día 0 + 7 × 86 400 − 1 s da cierto; en día 0 + 7 × 86 400 s da falso y `.ended`.
- `testNothingChangesBetweenSessionStarts`: tras evaluar en el día 6, `grantsFullAccess` y `status` siguen igual hasta que se evalúa en el día 8, que da falso.
- `testClockSetBackDoesNotExtendTheTrial`: evaluar en día 6, luego en día 1 (reloj atrasado) sigue dando cierto con `consumed` = 6 días; evaluar en día 2 + 1 s da falso.
- `testEndedTrialDoesNotRestart`: terminada, `start` devuelve falso y sigue `.ended`.
- `testStateSurvivesANewInstance`: otra `NightTrial` sobre el mismo almacén ve el mismo registro; una terminada sigue terminada sin evaluar.
- `testNightsRemainingFollowsTheCalendar` (Europe/Madrid): en el día 0 a las 23:00, 7; el 17-11 a las 23:30, 6; el 18-11 a la 01:00, 5; el 22-11 a las 23:30, 1; el 23-11 a las 22:00, 1; el 23-11 a las 23:30 sin haber evaluado, 1. *Corregido en la revisión (17-11-2026): la noche se ancla al día en que empezó, así que el 18-11 a la 01:00 da 6, no 5, como pide la frase de 08 §2.4; ese test fija su inicio a las 23:00 y el día 0 del resto pasa a las 20:00, fuera de `NightWindow`. ### A4 · `SmallHoursRecipe`, la receta de Madrugada (C05, C60, 06 §2.5)

Datos puros. Madrugada es una receta fija para todos: océano a nivel bajo con Marea a 8 por minuto, 20 minutos, entrada de 3 s; la Marea guía hasta el minuto 10,5 y se disuelve hasta el 13; el mar funde los últimos 5 minutos ("Se retira · n min"); al terminar no pasa nada.

```swift
struct SmallHoursRecipe: Equatable {
    let sound: SoundID                  // .ocean
    let level: Float                    // 0.3
    let breathsPerMinute: Int           // 8
    let duration: TimeInterval          // 1_200
    let fadeIn: TimeInterval            // 3
    let tideGuideEnd: TimeInterval      // 630
    let tideDissolveEnd: TimeInterval   // 780
    let finalFade: TimeInterval         // 300

    static let standard: SmallHoursRecipe
    var finalFadeStart: TimeInterval { get }   // duration - finalFade = 900

    enum Phase: Equatable { case tideGuiding, tideDissolving, plainSea, windingDown, finished }
    func phase(at elapsed: TimeInterval) -> Phase
    func minutesLeft(at elapsed: TimeInterval) -> Int
    func windingDownMinutes(at elapsed: TimeInterval) -> Int?
}
```

- `phase(at:)`, con el tiempo negativo tratado como 0: `[0, 630)` `tideGuiding`; `[630, 780)` `tideDissolving`; `[780, 900)` `plainSea`; `[900, 1200)` `windingDown`; desde 1200, `finished`.
- `minutesLeft(at:)`: minutos que quedan, redondeados hacia arriba, nunca menos de 0.
- `windingDownMinutes(at:)`: `minutesLeft` durante `windingDown` y `nil` fuera.
- Solo tipos de `SleepNoise/Model`. No uses `BreathParameters` ni nada de `SleepNoise/Audio/`.

Tests en `SmallHoursRecipeTests`:

- `testStandardRecipeMatchesTheDecision`: los ocho valores de arriba.
- `testTimelineIsOrdered`: `0 < fadeIn < tideGuideEnd < tideDissolveEnd <= finalFadeStart < duration`.
- `testPhaseEdges`: −5 y 629,9 `tideGuiding`; 630 `tideDissolving`; 780 `plainSea`; 900 `windingDown`; 1200 `finished`.
- `testMinutesLeftCountsDown`: en 0 y en 1 s, 20; en 60, 19; en 1199, 1; en 1200, 0.
- `testWindingDownMinutes`: en 899, `nil`; en 900 y 901, 5; en 960, 4; en 1199, 1; en 1200, `nil`.
